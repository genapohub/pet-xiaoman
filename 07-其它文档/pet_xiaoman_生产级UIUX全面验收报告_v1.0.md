## 三、已修复问题

### 1. 微信启动 scene 误当门店 slug

问题：

微信开发者工具普通启动会带 `options.scene=1001`。旧逻辑把这个值当作门店 slug，请求：

`/api/c/store/profile?slug=1001`

结果导致品牌 404，普通搜索/开发者工具启动时有概率回落成中性品牌。

修复：

- `options.scene` 明确作为微信入口场景值处理，不再当业务 slug。
- 只识别 `query.slug` 与 `query.scene` 里的业务参数。
- 补充校验用例：`scene=1001` 不再作为门店 slug。

涉及文件：

- `06-项目编码/pet_xiaoman_miniapp/utils/brand.js`
- `06-项目编码/pet_xiaoman_miniapp/scripts/verify-brand.js`

### 2. C 端首页白标口吻优化

问题：

首页首屏眉标使用“本地宠物善终服务”，在多门店白标下更像平台通用文案。

修复：

- 改为“门店专属服务”，降低平台感，更符合用户从某个门店入口进入后的预期。

涉及文件：

- `06-项目编码/pet_xiaoman_miniapp/pages/index/index.wxml`

## 四、C 端 UI/UX 验收

### 通过项

- 登录页已按门店白标渲染：店名、标语、主色可随门店 profile 切换。
- 未配 logo 时使用店名首字占位，不借用其它门店品牌资产。
- 首页信息层级基本合理：门店品牌 -> 三承诺 -> 立即预约 / 价格表 -> 电话 / 地址。
- 预约页围绕“选套餐、填宠物、选日期、接送地址、提交预约”组织，流程直观。
- 收银台已按支付配置展示可用/不可用状态，未配置微信支付时不会误导用户付款。
- 登录、退出、个人中心详情页、承诺详情页已进入 C 端主流程闭环。

### 仍需人工复核

- 微信开发者工具截图帧与 AX 页面树出现不同步：页面树已读到首页/预约页，但截图文件仍停在登录页。因此本轮 C 端“视觉截图”只可作为部分证据，最终仍需要人工在开发者工具中逐页截图确认。
- 真机安全区、底部 tab、弹窗层级、长文本换行需要在至少一台真机或微信开发者工具真机预览里再过一遍。

## 五、B 端 UI/UX 验收

### 通过项

- 登录页中性化，不再硬编码某家门店品牌；平台/门店登录入口统一。
- 左侧菜单已按角色区分：
  - 平台超管只有“门店管理”。
  - 店长有工作台、订单、价格、纪念品、寄存、客户、数据、团队、权限。
- 后台组件化基础成立：
  - 页面头部统一使用 `PxPageHeader`。
  - 表格页统一使用 `PxTablePage`。
  - 空态统一使用 `PxEmpty`。
  - 操作按钮统一使用 `PxActionButton`，带图标和提示。
  - 抽屉表单统一使用 `PxFormDrawer`。
- 菜单图标、操作图标已经覆盖主要模块，符合后台可扫读体验。
- 平台门店详情已把品牌 UI、小程序入口、扫码入口、门店账号放进同一个管理视图，功能层级清楚。

### 风险项

- 登录后的后台页面截图未能稳定自动落图，原因是本机 Chrome headless 复用登录态失败；已用接口、源码结构和构建结果完成替代验收。
- `npm run build` 仍有 Element Plus 大 chunk 警告，不影响当前试运营，但 V1.1 可考虑继续拆分。
