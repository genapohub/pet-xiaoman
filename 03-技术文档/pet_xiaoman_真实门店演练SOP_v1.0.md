# pet_xiaoman_真实门店演练SOP_v1.0

> 日期：2026-09-13  
> 目的：用一套真实门店资料，把平台开店、C 端入口、B 端履约完整跑一遍。  
> 适用阶段：V1.0 试运营前。

---

## 一、演练目标

本 SOP 只验证一件事：

> 真实门店是否能用宠小满完成从获客入口到订单完成的闭环。

不在本轮解决平台经营看板、自助入驻、复杂装修、平台收费等 V2.0 问题。

---

## 二、演练角色

| 角色 | 账号来源 | 负责动作 |
|---|---|---|
| 平台超管 | `superadmin` 或真实超管账号 | 开店、配品牌、开门店账号 |
| 店长 | 新门店店长账号 | 配价格、看订单、管理员工 |
| 店员 | 店长或超管创建 | 处理订单、上传影像 |
| 顾客 | 小程序本地/真机预览 | 浏览、下单、查看进度 |

---

## 三、资料准备

| 类型 | 必填项 | 备注 |
|---|---|---|
| 门店基础 | 对外店名、内部店名、slug | slug 用英文/数字/短横线，建好后不建议修改 |
| 品牌 UI | logo、主色、标语 | logo 可先留空，用店名首字占位 |
| 联系信息 | 电话、地址、营业时间 | C 端首页、个人中心、承诺页会展示 |
| 小程序入口 | 小程序名称、AppID、默认入口状态 | 暂无 AppID 可先留空，扫码 slug 入口仍可验证 |
| 账号 | 店长姓名、账号、初始密码 | 真实试运营前不要使用默认密码 |
| 价格 | 服务套餐、单项服务、加购项 | 至少准备 3 个服务项 |
| 商品 | 纪念品名称、价格、图片 | 可先用本地图或占位图 |

---

## 四、演练步骤

### 1. 平台开店

1. 超管登录后台。
2. 进入「门店管理」。
3. 点击「开通门店」。
4. 填写门店基础、品牌、联系信息、首位店长账号。
5. 保存后进入门店详情。

通过标准：

- 门店列表出现新门店。
- 门店状态为营业中。
- 品牌与 UI、门店账号、小程序入口三个区域均可打开。

### 2. 配置品牌与入口

1. 在门店详情确认品牌预览。
2. 补齐联系电话、地址、营业时间。
3. 若已有微信小程序 AppID，填写小程序名称和 AppID。
4. 复制开发者工具启动路径或二维码参数。

通过标准：

- 门店详情“品牌白标、门店联系、后台账号”均显示已就绪。
- 没有 AppID 时，“独立小程序”可暂时待完善，不阻断扫码入口验证。

### 3. 门店账号登录

1. 退出超管。
2. 使用新门店店长账号登录后台。
3. 检查门店后台品牌色是否与新门店一致。
4. 确认店长看不到平台「门店管理」。

通过标准：

- 店长只能看到本店履约菜单。
- 当前门店名称、主色和 C 端资料一致。

### 4. 配置服务与商品

1. 打开「服务项目」。
2. 新增或编辑至少 3 个服务项。
3. 打开「纪念品管理」。
4. 新增至少 1 个纪念品。
5. 保存后打开 C 端价格表和纪念品页。

通过标准：

- C 端展示的服务价格与后台一致。
- 商品图片、价格、状态在 C 端可见。

### 5. C 端入口验证

1. 开发者工具用 `pages/index/index?slug=新门店slug` 启动。
2. 检查首页品牌、电话、地址、营业时间。
3. 打开价格表、服务详情、个人中心、承诺页。
4. 若有独立 AppID 配置，切换 `DEFAULT_STORE_SLUG` 后无参数启动验证。

通过标准：

- C 端不会显示其他门店的店名、标语、logo。
- 所有业务接口均使用当前门店 slug。

### 6. 跑一笔完整订单

1. 顾客在 C 端选择服务并提交预约。
2. 店长/店员在今日工作台看到新订单。
3. 店员确认订单。
4. 店员流转接宠、服务中、待交付、已完成。
5. 在关键节点上传影像。
6. 顾客回到 C 端订单详情查看时间线。

通过标准：

- 订单状态正向流转。
- C 端订单详情看到正确时间线。
- 影像与订单关联正确。
- 不出现其他门店数据。
