# pet_xiaoman_人工冒烟脚本_v1.0

> 日期：2026-09-13  
> 目的：用 PyCharm + 微信开发者工具验证当前 V1.0 RC 是否能完整跑起来。  
> 原则：先确认启动与主链路，再看细节 UI；发现阻断问题先记录，不边测边扩需求。

## 一、前置准备

### 1. 本地服务

| 服务 | PyCharm 配置 | 地址 |
|---|---|---|
| API | `API FastAPI 8010` | `http://127.0.0.1:8010` |
| 后台前端 | `后台前端 5173` | `http://127.0.0.1:5173` |
| 小程序 | 微信开发者工具打开 `pet_xiaoman_miniapp` | API 默认连 `8010` |

### 2. 默认账号

| 身份 | 账号 | 密码 | 用途 |
|---|---|---|---|
| 平台超管 | `superadmin` | `super123456` | 开店、配品牌、开号 |
| 示例门店店长 | `petxiaoman` | `petxiaoman123` | 门店后台履约 |

> 以上仅用于本地联调。真实试运营前必须更换真实账号和密码。若历史本地库中店长密码不一致，先在 API 目录执行：`PYTHONPATH=. SQLITE_FALLBACK=true .venv/bin/python -m scripts.migrate_dev_accounts --apply`。

### 3. 启动顺序

1. 在 PyCharm 启动 `API FastAPI 8010`。
2. 浏览器打开 `http://127.0.0.1:8010/healthz`，应返回 `{"ok":true}`。
3. 在 PyCharm 启动 `后台前端 5173`。
4. 浏览器打开 `http://127.0.0.1:5173/login`。
5. 微信开发者工具打开 `06-项目编码/pet_xiaoman_miniapp`。

## 三、平台超管冒烟

1. 使用 `superadmin / super123456` 登录后台。
2. 确认左侧只显示「门店管理」。
3. 在门店列表确认至少有「宠小满·示例门店」。
4. 进入门店详情，检查三块内容：
   - 品牌与 UI：店名、标语、主色、电话、地址、营业时间。
   - 小程序入口：默认 slug、二维码参数、独立小程序 AppID 配置位。
   - 门店账号：店长、店员账号列表。
5. 若使用真实门店资料，创建一条新门店并记录：

| 字段 | 记录 |
|---|---|
| 门店名称 |  |
| slug |  |
| 小程序名称 |  |
| AppID |  |
| 店长账号 |  |

通过标准：

- 超管不会进入订单、客户、商品等租户履约页面。
- 新门店保存后，门店列表能看到品牌、主色、账号数和状态。
- 停用门店时有明确风险提示。

## 四、门店后台冒烟

1. 退出超管，使用门店店长账号登录。
2. 检查左侧菜单：
   - 今日工作台
   - 订单管理
   - 服务项目
   - 纪念品管理
   - 寄存管理
   - 客户档案
   - 数据看板
   - 员工/角色权限
3. 检查门店后台品牌色是否跟当前门店一致。
4. 打开订单管理，默认应显示全部订单，日期为空。
5. 打开服务项目和纪念品管理，确认列表能加载，增删改查按钮可见。

通过标准：

- 门店账号看不到「门店管理」平台菜单。
- 店员账号看不到店长级敏感入口或按钮。
- 列表接口不串店，无法看到其他门店订单和客户。

## 五、C 端小程序冒烟

### 1. 默认入口

1. 不带启动参数进入小程序。
2. 确认加载 `DEFAULT_STORE_SLUG` 对应门店。
3. 首页、价格表、纪念品、个人中心能正常打开。

### 2. slug 入口

1. 在开发者工具启动路径填：`pages/index/index?slug=chongxiaoman`。
2. 确认门店品牌、标语、主色正确。
3. 切换到另一门店 slug，确认品牌和数据随 slug 切换。

### 3. 主页面检查

| 页面 | 检查重点 |
|---|---|
| 首页 | 品牌、联系电话、服务入口、承诺模块 |
| 价格表 | 服务项目、价格版本、预约入口 |
| 服务详情 | 套餐说明、科普内容、预约入口 |
| 预约下单 | 宠物信息、地址、时间、费用确认 |
| 收银台 | 到店付可用；未开支付时不阻断下单 |
| 订单列表 | 能看到本门店订单 |
| 订单详情 | 时间线、影像、取消/改期入口 |
| 个人中心 | 登录、资料详情、退出、承诺页 |

## 六、完整订单链路冒烟

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 1 | C 端提交预约 | 生成订单号，进入待确认 |
| 2 | B 端今日工作台查看 | 新订单出现 |
| 3 | B 端确认订单 | 状态进入待接宠/已确认 |
| 4 | B 端流转到服务中 | 状态更新，C 端可见 |
| 5 | B 端上传影像 | 订单详情可查看影像 |
| 6 | B 端交付并完成 | 订单进入已完成 |
| 7 | C 端查看订单详情 | 时间线完整，门店数据正确 |

阻断标准：

- 任何一步 404、白屏、保存失败、状态无法流转，都记为 P0。
- 影像上传失败但订单可继续履约，记为 P1。
- 文案或 UI 不够精致但不影响流程，记为 P2。
