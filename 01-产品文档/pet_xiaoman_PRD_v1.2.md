## 2. 需求背景

### 2.1 需求来源
门店已开业且有真实订单，目前获客靠小红书「宠物善终账号」矩阵，接单靠微信私信 + 电话 + 手工记账。竞品分析确认了本地赛道的差异化杠杆：**透明定价 + 不推销 + 过程体面**（用户自发传播的「第25小时」案例证明信任感>价格敏感度）。本系统要把这套信任打法从「人肉承诺」升级为「产品能力」——价格全公开、服务过程影像化、24 小时可预约。

### 2.2 现状分析
- **接单链路断裂**：深夜离世场景（用户核心痛点「怕没人管」）目前靠老板手机 24h 待命，错过即流失；预约信息（宠物情况/地址/期望时间）散落在聊天记录里，门店无法排期。
- **信任无法规模化**：价格透明靠小红书置顶图片，聊天里仍可能被问「还有别的费用吗」；服务过程（告别/单独火化）目前只对到店客户可见，未到店客户看不到「钱花在哪」。
- **复购与转介绍无抓手**：宠物档案、服务记录、纪念品加购全靠老板记忆；「毛发爪印留存」等高口碑项目没有被主动推荐过。

### 2.3 问题与痛点（按竞品分析频次排序）
| 用户痛点 | 系统对策 | 功能落点 |
|---|---|---|
| 怕被宰（低价引流→到店加价） | 价格全量公开、订单确认后锁价、加价需线上审批留痕 | C002 价格表、B005 价格配置 |
| 怕不体面（流程草率/担心混灰） | 单独火化承诺写进服务项；关键环节影像同步给客户 | C006 进度时间线、B004 影像上传 |
| 怕没人管（深夜找不到服务） | 24h 可下单 + 接单响应 SLA（30 分钟内确认） | C004 预约、B001 工作台提醒 |
| 情感残留（毛发/爪印/纪念品） | 加购项在下单与交付两个节点主动展示；寄存到期提醒 | C007 纪念品、B007 寄存管理 |
| 首次决策无经验 | 流程科普页（商业善终 vs 无害化处理、单独/集体火化区别） | C003 服务详情内嵌科普 |

## 3. 需求目标

### 3.1 业务目标
1. 把现有订单流程线上化：上线 1 个月内，90% 新订单走小程序预约（替代微信私信记录）。
2. 让「透明」可感知：订单进度影像覆盖率 100%（每单 ≥3 个关键节点影像）。
3. 提升客单与口碑：纪念品/寄存加购率 ≥25%（当前无数据，行业参考值 15-20%，依据：竞品 UGC 中纪念品是高口碑点）；上线 3 个月内因服务体验产生的转介绍 ≥10 单。

### 3.2 用户目标
- 宠物主：3 分钟完成预约；全程不用打电话也能知道「我的宠物现在在哪个环节、是否被单独对待」；悲伤期不用反复问价格。
- 门店员工：所有订单一个工作台看清「今天要接谁、做什么、上传什么」；影像上传就是日常工作流的一部分，不是额外负担（每节点 ≤2 分钟完成上传）。

### 3.3 衡量指标
- **北极星指标：月完成服务单量**（代表门店生意本身的增长，系统所有功能服务于它）。
- KPI 拆解：预约转化率（价格表页 UV → 提交订单，目标 ≥12%，依据：私信咨询→成交的行业口径 10% 左右，透明价格页应提升说服效率）；**线上支付渗透率 ≥40%**（下单订单中付定金/全款占比，依据：透明价格+公司主体信任背书，保守取四成；该指标同时验证「先收款」对爽约率的改善）；30 分钟接单达成率 ≥95%；影像节点覆盖率 100%；纪念品加购率 ≥25%（口径：线上购买 + 现场加购）；回访好评率 ≥90%。

## 4. 目标用户

### 4.1 用户画像
- **C 端 · 郑州本地宠物主**：25-45 岁女性为主（竞品评论区画像），宠物已离世或预知临终（老年/重病）；一生只用 1-2 次，零经验、高情绪、决策依赖搜索与口碑；支付意愿 500-2500 元（竞品价格带）。
- **B 端 · 门店店员（1-2 人）**：负责接单、接送、告别仪式主持、火化执行、影像拍摄上传；智能手机熟练但厌恶复杂操作——B 端一切页面以「少输入、多选择、大按钮」为原则。
- **B 端 · 店长/老板**：门店全权限（v2.0 起含入驻门店的店长）。
- **B 端 · 平台管理员（哥拿坡）**：跨店权限——门店开通/停用、平台级数据查看；自营店店长与平台管理员可为同一人。

### 4.2 使用场景
- **深夜突发（22:00-7:00，占比约 40%）**：宠物刚离世，搜索找到小程序，看价格表→立即下单→店员手机收到提醒→30 分钟内电话确认。**MVP 不做在线支付，下单即预约，到店/服务完成时线下收款**（理由见 §5.1 不做清单）。
- **预期临终预约**：老年/重病宠物主提前 1-7 天预约，需要改期——支持一次免费改期。
- **服务中查看**：接送到达、告别仪式、火化开始/完成等节点，店员上传影像，客户在订单页实时看到。
- **交付与后续**：骨灰交付时确认纪念品加购；寄存客户到期前 7 天小程序提醒；30 天后自动生成回访任务。

### 5.2 功能详述（核心功能 · 开发可执行粒度）

#### 5.2.1 预约下单（C004）
- **功能说明**：宠物主选择服务套餐（含加购项）→ 填写宠物信息（名字/种类/体重）→ 选择期望服务时间与接送地址 → 提交预约 → **进入收银台，三选一：付定金 / 付全款 / 暂不支付（到店付）**。提交即预约成功（支付可选，不阻塞），店员 30 分钟内电话/微信确认。
- **用户操作**：选套餐（默认勾选「单独火化」，不可取消但可看说明）→ 表单填写（宠物名必填、种类选择、体重选填）→ 地址（微信一键获取位置 + 手动补详细地址）→ 提交后看到「已提交，30 分钟内确认」+ 订单号。
- **业务规则**：①夜间单（22:00-7:00 提交）自动标红置顶到 B001；②同一宠物主有「服务中」订单时不允许重复下单（提示联系门店）；③提交后价格锁定为提交时刻的价格版本，后续调价不影响已确认订单；④支付为可选动作，三种模式随时可切换（未接宠前定金可补成全款）；⑤微信支付前提：商户号已开通（见 §10.1 前置依赖）。
- **异常处理**：定位授权被拒→退化为手动输入地址；提交超时→本地草稿保留，恢复后一键重提；服务时间与已有排期冲突→提交时提示「该时段已有安排，门店将电话与你协商」，不硬阻断（善终有时效性，不能因排期满拒绝客户）。
- **相关页面**：C002 → C004 → C005。
- **验收标准**：
  - Given 用户在价格表选中「基础告别套餐」，When 提交预约（宠物名=豆豆、次日 10:00），Then 生成订单号 GD+日期+3 位序号、状态=待确认、B001 工作台 15 秒内出现该单且夜间单标红。
  - Given 提交时网络中断，When 网络恢复后重新进入页面，Then 表单数据从本地草稿恢复并可一键重提，不产生重复订单。
  - Given 用户已存在「服务中」订单，When 再次提交预约，Then 拦截并展示提示文案，不生成订单。

#### 5.2.2 订单状态流转 + 影像上传（B003/B004，C006 消费端）
- **功能说明**：店员在 B003 执行状态流转，关键节点（接宠完成/告别仪式/火化完成/交付完成）强制上传影像后才能流转到下一状态；影像实时同步 C006 时间线，客户订阅消息收到节点通知。
- **用户操作（店员）**：订单详情点「开始接宠」→ 到达后拍照上传（≥1 张）→ 系统自动流转状态并通知客户。上传支持拍照和相册，单张 ≤10MB，视频 ≤60 秒 ≤50MB。
- **业务规则**：①强制影像节点：接宠完成、告别仪式、火化完成（交付完成节点建议但非强制）；②影像一经同步客户不可撤回（撤回需店长权限并留操作日志）；③状态只能按状态机正向流转，回退需店长权限。
- **异常处理**：上传失败（弱网）→ 自动重试 3 次后转手动重传，状态流转被阻塞并提示；客户未订阅消息→不影响流转，时间线为准。
- **验收标准**：
  - Given 订单处于「接宠中」，When 店员上传 2 张照片并点「确认到达门店」，Then 订单状态变为「服务中」、C006 时间线新增节点且影像可见、客户收到订阅消息。
  - Given 店员尝试流转「火化完成」但未上传任何影像，When 点击流转按钮，Then 拦截并提示「该节点需至少 1 张影像」。
  - Given 店员在弱网环境上传视频失败 3 次，When 重试入口出现，Then 状态未被流转，已上传成功的照片不丢失。

#### 5.2.3 服务项目与价格配置（B005）
- **功能说明**：店长维护套餐/单项/加购三级价格体系；每次价格变更生成新版本号，C002 展示最新版本，已确认订单锁定下单时版本。
- **验收标准**：
  - Given 店长将「单独火化（10kg 内）」从 800 元改为 880 元并保存，When 客户打开 C002，Then 显示 880 元及「09-05 生效」标记；此前已确认订单详情仍显示 800 元。
  - Given 店长删除一个已被历史订单引用的加购项，When 保存，Then 系统改为「下架」而非物理删除，历史订单展示不受影响。

#### 5.2.4 纪念品展示与寄存（C007/C008，B006/B007）
- **功能说明**：纪念品「**线上展示购买 + 到店选购**」双通道——C007 单件直购（微信支付，随单交付或到店自取）；下单页仍可勾选意向纪念品作为备注（到店选购）；寄存提供登记（寄存人/宠物/位置/期限）与到期提醒。
- **不做说明**：不做购物车/优惠券/营销活动、不做快递物流。理由：纪念品是情感陪伴型消费，单件直购已覆盖线上冲动购买场景；完整电商的购物车/物流/营销体系对单店是负资产。二期视线上购买转化数据决定是否扩展。
- **验收标准**：
  - Given 寄存单录入到期日为 2026-10-05，When 系统到达 2026-09-28，Then B007 该记录标黄且生成提醒任务。
  - Given 客户在 C008 查询寄存，When 输入手机号后四位验证通过，Then 展示寄存位置与剩余天数，不暴露其他客户信息。
  - Given 客户在 C007 对某纪念品点「立即购买」并支付成功，When 查看订单/商品记录，Then 生成购买记录（支付流水关联），履约方式为随单交付或到店自取，无快递单。

#### 5.2.5 客户档案与回访（B008/B009，C009）
- **功能说明**：订单完成后自动生成客户档案（宠物+主人+服务历史+来源渠道）；完成 30 天后自动生成回访任务，店员登记回访结果（满意度/是否愿意推荐）。
- **验收标准**：
  - Given 订单状态变为「已完成」，When 30 天后，Then B008 生成回访任务，完成回访登记后任务关闭并记录来源标记。

#### 5.2.6 在线支付（定金 / 全款 / 到店付三模式）
- **功能说明**：预约提交后客户在收银台自主选择：**①付定金**（套餐价 × 定金比例，默认 20%，B005 可配置，最低 100 元）**②付全款** **③暂不支付（到店付）**。尾款在服务交付时到店结清，店员在 B003 标记「尾款已收」+实收金额。纪念品线上购买复用同一支付通道（单件直购）。
- **用户操作**：C004 提交后进入收银台 → 选支付方式 → 微信支付 → 支付结果页；C006 订单页展示支付状态（已付定金 X 元 / 尾款 Y 元到店支付 / 已全款 / 到店付）。
- **业务规则**：
  ① 支付不阻塞预约：不支付 = 到店付，门店电话确认时口头确认即可，店员可见支付状态列；
  ② **退款规则**：接宠完成前取消 → 已付金额全额原路退回（系统自动发起，1-3 个工作日到账）；接宠完成后取消 → 服务已发生不可退（取消弹窗明示）；
  ③ 纪念品线上购买 = 单件直购（无购物车、无优惠券），支付后标记「随单交付」或「到店自取」，**不做快递物流**（本地生意，单店自提半径内）；
  ④ 微信支付回调验签 fail-check（沿用宠宝树经验：验签失败拒绝处理），回调未达时 5 分钟对账任务补偿；
  ⑤ **价格表全量单项价对外公开**（含单项火化按体重分档价、全部加购价）——B005 每次保存价格即对外承诺变更，保存前二次确认并展示「将公开生效」提示；
  ⑥ 「已完成」状态前置校验：pay_type 必须为 全款已付 或 到店付已结清（线下收款由店员标记），否则不可流转。
- **异常处理**：支付超时/失败→收银台重试，可换到店付；退款发起失败→后台标记人工处理并告警；并发重复支付→后端幂等（order_no+金额），多收部分自动原路退回。
- **验收标准**：
  - Given 客户提交 800 元套餐订单，When 选付定金（20%=160 元）并支付成功，Then pay_type=定金已付、C006 显示「已付定金 160 元，尾款 640 元到店支付」、支付流水落库含微信 transaction_id。
  - Given 已付定金订单在接宠完成前取消，When 取消成功，Then 系统自动发起全额原路退款，refund_status 流转 退款中→已退款。
  - Given 服务中订单客户主动补全款，When 支付成功，Then pay_type=全款已付，交付环节无需再收款。
  - Given 到店付订单交付完成，When 店员标记「尾款已收」并录入实收金额，Then 订单结清，「已完成」可流转。
  - Given 并发发起两笔支付且都回调成功，When 对账任务运行，Then 识别超额支付并自动原路退回多收部分，留对账记录。
  - Given 未付任何款项的订单交付完成，When 店员尝试流转「已完成」但未标记尾款已收，Then 拦截并提示「请先确认收款」。

## 6. 业务流程

### 6.1 主流程
```
客户发现（小红书/搜索/转介绍）
→ C002 查看透明价格 → C004 提交预约（价格锁定）
→ 系统生成订单[待确认] → B001 提醒（夜间单标红）
→ 店员 30 分钟内电话确认 → [已预约]
→ 按约上门 → 上传「接宠完成」影像 → [接宠中]→[服务中]
→ 告别仪式（影像）→ 火化（影像，强制）→ [待交付]
→ 骨灰交付 + 纪念品现场加购 → [已完成]（线下收款）
→ 30 天后回访任务 → [已回访]
```

### 6.2 异常流程
- **联系不上客户**（待确认超 2 小时）：B001 置顶提醒 → 店员第二次外呼 → 仍失联则订单转「已取消（失联）」并留存记录，客户侧可重新预约。
- **影像上传持续失败**：允许店长权限「无影像流转」，标记例外并记录原因（保证业务不断，但事后必须补传）。
- **客户改期**：免费改期 1 次，改期后 B001 生成排期冲突提示（如与新单撞时）。

### 6.3 分支流程
- **到店自送**（非接送）：预约时可选「自行送达」，跳过接宠节点，影像强制节点少一个。
- **夜间紧急单**：22:00-7:00 下单，店员手机订阅消息+电话兜底；系统不做自动派单（单店无需）。
- **纪念品现场加购**：交付环节店员在 B003 追加加购项，价格按当前版本，客户确认后计入订单总额。

### 6.4 状态机定义（订单）

**状态清单**：

| 状态 | 含义 | 是否终态 |
|------|------|:-------:|
| 待确认 | 已提交预约，待店员电话确认 | 否 |
| 已预约 | 确认完成，等待按约服务 | 否 |
| 接宠中 | 店员已出发接送 | 否 |
| 服务中 | 宠物已到店，告别/火化执行中 | 否 |
| 待交付 | 火化完成，待骨灰/纪念品交付 | 否 |
| 已完成 | 交付完成、款项已收（线下） | 是 |
| 已取消 | 客户取消/失联/门店取消 | 是 |

**合法流转表**：

| 当前状态 | 可流转至 | 触发条件 | 触发动作 |
|---------|---------|---------|---------|
| 待确认 | 已预约 | 店员电话确认成功 | 店员操作（SLA 30 分钟，超 15 分钟红色提醒） |
| 待确认 | 已取消 | 客户取消 / 失联超 2 小时 | 客户操作 / 店员操作（必填原因） |
| 已预约 | 接宠中 | 店员出发接宠 | 店员操作 |
| 已预约 | 已取消 | 客户改期不成取消 | 客户/店员操作 |
| 接宠中 | 服务中 | 到店，上传「接宠完成」影像 | 店员操作（影像强制，到店自送则由本状态跳过） |
| 服务中 | 待交付 | 火化完成，上传影像 | 店员操作（影像强制） |
| 待交付 | 已完成 | 交付+收款确认 | 店员操作（可追加现场加购） |
| 任意非终态 | 已取消 | 见 §6.2 | 需店长权限（服务中/待交付取消必填原因+审计） |

**流转规则**：终态不可流转；「已完成」原则上不可回退，确需回退（如收款纠纷）由店长操作并强制原因；状态回退全量写审计日志（操作人/时间/原因）。

**支付子状态（payment_status，独立于订单主状态机，随支付动作/线下标记流转）**：

| 支付状态 | 含义 | 流转 |
|---------|------|------|
| 未支付 | 到店付或尚未选择 | → 定金已付 / 全款已付 / 到店付已结清 |
| 定金已付 | 已付定金 | → 全款已付（补款）/ 到店付已结清（交付结清尾款）/ 退款中（取消） |
| 全款已付 | 已结清 | → 退款中（接宠前取消） |
| 到店付已结清 | 店员标记尾款已收 | 终态（随订单） |
| 退款中 / 已退款 | 原路退款 | 退款中 → 已退款；退款失败转人工 |

约束：「已完成」要求 payment_status ∈ {全款已付, 到店付已结清}；主状态机与支付子状态解耦——未支付不影响预约/服务流转，只拦截「已完成」。

### 7.2 计算逻辑
- `total_amount` = 套餐快照价 + Σ加购快照价；加购在「待交付」前追加均按追加时刻价格版本，追加后重算并推送客户确认（订阅消息）。
- 夜间单判定：`created_at` 时间在 22:00-次日 7:00（东八区）。
- SLA：待确认状态持续 >15 分钟触发红色提醒，>30 分钟标记「超时」（看板统计达成率）。

### 7.3 数据来源
- 价格：B005 配置，客户侧只读快照；影像：店员上传，对象存储；来源渠道：客户首次下单时店员标记，可修正一次（保留修改痕迹）。

## 8. 非功能性需求

### 8.1 性能要求
- C 端页面首屏 ≤2s（4G）；影像上传支持断点续传（视频）；B 端表格查询响应 ≤1s（单店数据量小，<1 万单/年）。

## 10. 上线计划

### 10.1 发布策略
两个外部依赖并行启动：**① 类目提审**——类目选择「生活服务-殡葬服务」（公司主体已注册），提审前准备：门店营业执照、动物无害化处理/相关经营许可材料、服务协议与价格声明页（内容合规：不得出现「棺材」「遗体」等敏感词的营销化表达，文案统一用「宠物」「告别」「火化」中性表述）；**② 微信支付商户号开通**（在线支付前提）——公司主体申请微信支付商户号 + 关联小程序 + 开通 JSAPI 支付，周期约 1-3 个工作日，若商户号未及时开通，支付模块以功能开关关闭（收银台隐藏支付入口，全部到店付），不影响其余功能上线。提审与开发并行，预留 2 轮审核周期（每轮 1-3 天）。

### 10.2 灰度方案
门店已有真实订单，天然灰度：**第一阶段（1-2 周）系统只做记录**——新订单仍走微信接单，店员同步录入系统验证流程与影像上传习惯；**第二阶段**老客户引导小程序预约（小红书置顶价格表换成小程序码）；**第三阶段**全量，微信接单退出。任一阶段回退 = 回到微信接单（业务无损，这是单店系统的天然回滚优势）。

### 10.3 回滚预案
功能级：B005 下架出问题的服务项（C002 即时隐藏）；订单级：状态机异常单由店长回退并审计；系统级：小程序版本回退需重新提审（1-3 天），期间门店按纸质流程接单（与现状一致，可接受）。上线前 B 端做 1 次全流程演练（用真实订单走完 6.1 主流程）。

### 12.1 当前版本定位（v1.2 定稿）

### 12.2 迭代方向一：多租户后台（给郑州多家善终门店使用）

- **触发条件**：自营店模型跑通（月单稳定）+ 有同行门店表达使用意向
- **已完成的方案设计**（2026-09-05，原 v2.0 增补，移入本节存档）：邀请制人工开通（不做自助注册/在线计费）；全部业务表加 `shop_id` 行级隔离；价格配置/客户档案/数据看板按店隔离；C 端按门店进入（链接带 shop 参数）；**跨店客户数据不共享**——客户数据属门店资产，是对入驻店的信任承诺与卖点；平台管理员角色跨店只看汇总
- **技术方案**：见技术选型 ADR-006（Deferred）——共享库共享表 + shop_id，启用时一次性加列回填（单店数据量小，回填秒级）
- **工作量预估**：在 v1.2 基础上约 +2 周（B011 门店管理 + 隔离改造 + 权限调整）

### 12.3 迭代方向二：小程序品牌定制装修（白标能力）

- **说明**：C 端小程序支持按客户门店的品牌进行店铺 UI 定制装修（品牌色/logo/头图/承诺文案可配置），让系统可以作为「善终门店数字化基础设施」输出给同行，每家店的小程序呈现自己的品牌。
